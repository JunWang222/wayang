# Generic JDBC Local Engine Runbook

This document explains how to run the local checks for Presto, Trino, and
BigQuery, and how to read the result.

## Presto

Presto is implemented on the `presto-jdbc` branch.

Start local Presto:

```powershell
cd C:\wayang
git switch presto-jdbc
docker pull prestodb/presto:0.297
cd presto-setup
docker compose up -d
cd ..
```

Run the Wayang integration test:

```powershell
.\mvnw.cmd test -pl wayang-platforms/wayang-generic-jdbc "-Dtest=PrestoGenericJdbcIT" "-Drat.skip=true" "-Dmaven.javadoc.skip=true"
```

Expected summary:

```text
Tests run: 8, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

The Presto test prints visible verification blocks:

```text
[PRESTO VERIFY] Filter pushdown: region = 'APAC'
Direct Presto JDBC SQL:
  SELECT order_id, region, product, amount, order_date FROM orders WHERE region = 'APAC'
Direct Presto JDBC result (7 rows):
  ...
Wayang through Presto result (7 rows):
  ...
Comparison:
  sorted direct JDBC rows == sorted Wayang rows
```

It also checks Presto's own query history:

```text
[PRESTO VERIFY] Wayang SQL appears in Presto query history
Expected Wayang-generated SQL:
  SELECT * FROM orders WHERE product = 'server' AND amount > 2000
Presto history count before Wayang execution: N
Presto history count after Wayang execution : N+1
```

This proves two things:

- direct Presto JDBC results match Wayang-through-Presto results
- Presto `system.runtime.queries` records SQL generated by Wayang

Stop local Presto:

```powershell
cd presto-setup
docker compose down
cd ..
```

## Trino

The earlier Trino setup is on `origin/trino-jdbc`.

Start from a clean local branch:

```powershell
git switch -c local-trino-bigquery origin/trino-jdbc
cd trino-setup
docker compose up -d
bash ./scripts/run-init.sh
cd ..
```

Run Wayang through Trino:

```powershell
.\mvnw.cmd test -pl wayang-platforms/wayang-generic-jdbc "-Dtest=TrinoGenericJdbcIT" "-Pintegration,skip-prerequisite-check" "-Drat.skip=true" "-Dmaven.javadoc.skip=true"
```

The Trino test verifies that:

- Trino plugin, mappings, and channel conversions are registered
- Wayang-generated SQL appears in Trino `system.runtime.queries`
- direct Trino-style results and Wayang-through-Trino results match for scan,
  filter, projection, and filter-plus-projection cases

## BigQuery

There are two BigQuery paths.

Local emulator checks live in `origin/trino-jdbc` under `bigquery-setup`:

```powershell
git switch -c local-trino-bigquery origin/trino-jdbc
cd bigquery-setup
docker compose up -d
mvn test -Pintegration
```

The emulator verifies local BigQuery-like SQL behavior, but it does not fully
prove the Wayang BigQuery JDBC connector.

The Wayang BigQuery JDBC test uses real Google BigQuery and the official
BigQuery JDBC driver:

```powershell
.\mvnw.cmd test -pl wayang-platforms/wayang-generic-jdbc "-Dtest=BigQueryGenericJdbcIT" "-Pintegration,skip-prerequisite-check" "-Drat.skip=true" "-Dmaven.javadoc.skip=true"
```

It requires a service account key and real BigQuery table:

```text
~/wayang-bq-key.json
daeproject-316010.sales.orders
```

## Reading Results

Good result:

```text
BUILD SUCCESS
Failures: 0
Errors: 0
Skipped: 0
```

`Skipped > 0` usually means the engine was not reachable.

Wrong row count usually means the query ran, but the test expectation and seed
data disagree.

PowerShell Maven arguments should be quoted:

```powershell
.\mvnw.cmd test -pl wayang-platforms/wayang-generic-jdbc "-Dtest=PrestoGenericJdbcIT" "-Drat.skip=true" "-Dmaven.javadoc.skip=true"
```
